ACADEMDRM-CPP

Educational DRM (C++ and Python)

Project Overview

AcademDRM-Cpp is an educational DRM and anti-tamper prototype built to explore how modern software protection systems stitch together licensing, integrity validation, and protected feature gating. It consists of a native C++ client and a Python Flask license server that returns signed license payloads and enforces hardware-bound activation.

C++ Python Flask OpenSSL libcurl CMake vcpkg
View Repository

Highlights

  • End-to-end license flow: challenge request, signed response, and local signature verification.
  • Hardware binding: first successful activation binds the license to a hardware fingerprint (HWID).
  • Startup protections: anti-debug checks and in-memory .text integrity validation vs. the on-disk image.
  • Virtualized execution pipeline: a small DSL/compiler, bytecode encoding, and encrypted bytecode executed by a host-callback VM.
  • Protected feature gating: unlocks an ASCII donut animation only after successful validation.
  • Interactive diagnostics console: demonstrates each stage (startup checks, VM, full DRM journey) independently.

High-Level Architecture

C++ Client (Windows)

  • Collects HWID
  • Generates nonce + timestamp
  • Calls POST /validate
  • Verifies signature using public.pem
  • Runs anti-debug + integrity checks before unlocking protected logic

Python License Server (Flask)

  • Validates request fields + timestamp freshness
  • Checks license expiry / active status
  • Enforces HWID bind rules
  • Signs canonical JSON payload and returns {data, signature}
  • Uses SQLite as a simple license store

Validation Flow

  • Client sends: {license_key, hardware_id, nonce, timestamp}
  • Server responds: {data, signature} (signed)
  • Client verifies: signature + nonce match + status
  • Protected VM payload executes only on successful checks

What This Demonstrates

Software Protection Fundamentals

Explored licensing, payload signing, anti-replay basics (nonce/timestamp), and local verification patterns.

Systems + Security Mindset

Built defensive checks for process environment and code integrity, and designed clear failure behavior.

VM / Obfuscation Concepts

Implemented a small DSL-to-bytecode pipeline with encrypted bytecode executed by a custom VM to gate protected logic.

Tooling + Build Engineering

Used CMake with vcpkg (curl, OpenSSL, nlohmann-json) and a Python server stack (Flask, cryptography).

Project Notes

This is a learning-focused project meant for academic and defensive research. It is not production DRM and is not intended to be used as a sole protection layer for commercial software.
